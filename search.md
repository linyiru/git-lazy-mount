Readiness is observed by\npolling for the synthetic <code>.git</code> to appear, then running <code>git rev-parse --show-toplevel</code> / <code>--is-inside-work-tree</code>. Plain <code>git commit</code>, <code>git amend</code>, <code>git rebase</code>, and <code>git push</code> update normal Git state directly.</p>\n<p><strong>Do not use skip-worktree as a universal trick.</strong> The correctness baseline works\nwithout marking every index entry skip-worktree. The mount builds a full real\nindex from HEAD (<code>git read-tree HEAD</code>) and relies on FSMonitor, not on\nsparse/skip-worktree semantics, to keep <code>git status</code> cheap. (The interop bridge in\n<code>crates/git-store/src/interop.rs</code> <em>does</em> mark every entry skip-worktree, but that\nis a throwaway operational index for running stock Git against the shared store —\nnot the mount hot path.)</p>\n<p><strong>Directory listing must not hydrate file contents.</strong> <code>readdir</code> returns names,\ninode IDs, and <code>d_type</code> only — never exact sizes or blob reads. It merges baseline\ntree and overlay children at O(direct children). <code>readdirplus</code> is not enabled.</p>\n<p><strong>Do not buffer entire files per callback.</strong> All content paths are\nfile-descriptor / streaming based. Reads are serviced by <code>pread</code> into a cache\nfile; writes by <code>pwrite</code> into an overlay FD. Memory use is not proportional to\nblob size (reading a 64 MiB blob grows RSS by roughly one request-sized buffer,\nfar below the blob size; the test pins it under 24 MiB for a 64 MiB blob).</p>\n<p><strong>Real file handles; never <code>fh = 0</code>.</strong> Each successful open allocates a unique\nhandle (<code>next_fh</code> is an <code>AtomicU64</code> starting at 1). Reads and writes are serviced\nstrictly by handle, so open-unlink and rename-while-open work without a path.</p>\n<p><strong>Bounded pools, not thread-per-callback.</strong> FUSE callbacks run on two fixed-size\nworker pools (16 object-I/O threads + 4 metadata threads), never one OS thread per\nrequest.</p>\n<p><strong>Empty directories are real workspace state.</strong> An untracked empty directory is a\ndurable overlay <code>Dir</code> entry, not just an inode-table row; it survives lookup,\n<code>readdir</code>, unmount, and remount. Git omits empty directories from commits.</p>\n<p><strong>The change journal must be durable.</strong> A process-local <code>Mutex&lt;Vec&lt;…&gt;&gt;</code> is not a\nsufficient FSMonitor backing store. Changes are appended to a durable on-disk log\nthat is replayed on open, and any discontinuity yields a full-invalidation\nresponse.</p>\n<p><strong>Baseline + overlay model the working tree.</strong> The virtual working tree is a\nread-only baseline tree plus a writable overlay (see <a href=\"#52-working-tree-model-baseline--overlay\">§5.2</a>).</p>\n<p><strong>Linux only; no premature platform scaffolding.</strong> A crate that merely compiles\non another OS is not platform support. The shipped system is Linux / FUSE only.</p>\n<hr />\n<h1>5. The admin\ngitdir is configured with <code>core.worktree = &lt;mountpoint&gt;</code>, so stock Git resolves\nthe repo through the gitfile and operates on the mounted worktree using its normal\nindex, refs, locks, and hooks. The admin gitdir lives on a native filesystem,\nnever inside FUSE, so Git's <code>index.lock</code>, <code>packed-refs</code>, ref/config locks,\nreflogs, sequencer/merge/rebase state, and atomic renames all work normally.</p>\n<p>The synthetic <code>.git</code> is protected: any create/replace/delete/rename/chmod/write of\nit, or any attempt to create a path beneath it, fails safely. Protection is\nenforced in <code>Projection::child_path</code> (returns <code>ErrorCode::Authentication</code>), not by\na reserved inode. Instead\nthe parent command spawns a single <strong>detached, hidden <code>__serve</code> child</strong> that holds\nthe kernel mount:</p>\n<ul>\n<li><code>cmd_mount</code> does the clone/index/seed work, then spawns <code>git-lazy-mount __serve --gitdir … --mountpoint … --cache … --overlay …</code> with stdio nulled. The child is\nreparented to init and is <strong>not</strong> waited on; the parent polls for the synthetic\n<code>.git</code>, runs health checks, prints success, and exits.</li>\n<li><code>cmd_serve</code> (the <code>__serve</code> body) opens the <code>AdminRepo</code>, opens the\n<code>ChangeJournal</code>, builds the <code>Projection</code> with that journal, and calls\n<code>glm_fuse::mount</code>, which blocks until the mount is released.</li>\n<li><code>cmd_unmount</code> runs <code>fusermount3 -u</code> (falling back to <code>fusermount -u</code>, then\n<code>umount</code>); the serving child's <code>mount()</code> returns and it exits.</li>\n<li><code>cmd_doctor</code> reports mountpoint, mounted-or-not, and <code>show-toplevel</code>\n(optionally as JSON).</li>\n</ul>\n<p>The FSMonitor hook (<code>git-lazy-mount-fsmonitor</code>) and <code>sgrep</code> read the durable\njournal file directly — there is no socket and no protocol version to negotiate.</p>\n<h2>5.6 Startup sequence</h2>\n<p><code>cmd_mount</code> runs as a straight-line sequence:</p>\n<ol>\n<li><strong>Preflight.</strong> Create the mountpoint if needed and require it to be empty;\nderive the deterministic per-mountpoint workspace paths.</li>\n<li><strong>Clone.</strong> <code>AdminRepo::clone</code> runs <code>git clone --no-checkout --separate-git-dir=&lt;gitdir&gt;</code> with the default <code>--filter=tree:0</code>, sets\n<code>core.worktree=&lt;mountpoint&gt;</code>, adds <code>--no-single-branch</code> when <code>--depth</code> is set,\nand runs with <code>GIT_TERMINAL_PROMPT=0</code>. A full-object clone (filter rejected\nwith <code>--allow-full-object-clone</code>) still implies <strong>no</strong> checkout.</li>\n<li><strong>Build the index.</strong> <code>build_index</code> runs <code>git read-tree HEAD</code>, faulting the HEAD\ntree hierarchy and fetching <strong>zero</strong> blobs. This is O(tracked paths) of\nmetadata work and is reported honestly, never marketed as O(1).</li>\n<li><strong>Configure FSMonitor.</strong> Set <code>core.fsmonitor</code> to the\n<code>git-lazy-mount-fsmonitor</code> binary beside the executable, and\n<code>core.fsmonitorHookVersion=2</code>. (Nothing else is configured — no\n<code>untrackedCache</code>, no <code>hooksPath</code>, no <code>index.version</code>.)</li>\n<li><strong>Seed first status.</strong> Open the (empty) change journal, then\n<code>seed_fsmonitor_valid</code> so the <em>first</em> <code>git status</code> faults zero blobs (see\n<a href=\"#64-fsmonitor-v2--change-journal\">§6.4</a>).</li>\n<li><strong>Serve.</strong> Spawn the detached <code>__serve</code> child.</li>\n<li><strong>Validate.</strong> Poll <code>mountpoint/.git</code> for readiness (up to 1000 × 10 ms), then\nrun the health checks and print success.</li>\n</ol>\n<p>The startup ordering and its deadlock-avoidance constraints are owned by\n<a href=\"/git-lazy-mount/deadlock-startup-recovery\"><code>deadlock-startup-recovery.md</code></a>.</p>\n<h2>5.7 The <code>tree:0</code> default and its rationale</h2>\n<p>The default partial-clone filter is <strong><code>tree:0</code></strong>: every commit is fetched (so\nhistory, merge-base, <code>git log</code>, and branch switching all work), but no trees or\nblobs are. <code>build_index</code> then faults only the HEAD tree hierarchy; blobs hydrate\non read. This is both correct and cheap.</p>\n<p>Two alternatives are deliberately not the default:</p>\n<ul>\n<li><strong><code>--depth 1</code> (shallow)</strong> grafts the commits, which breaks <code>git merge</code> / <code>git rebase</code> and hides history. Not a default.</li>\n<li><strong><code>blob:none</code></strong> with full history would download <strong>every tree from all of\nhistory</strong> — slow and large on big repos. Not a default.</li>\n</ul>\n<p><code>blob:none</code> and <code>--depth</code> remain valid <strong>explicit</strong> overrides:</p>\n<pre><code class=\"language-bash\">git lazy-mount &lt;url&gt; &lt;path&gt; --branch main\ngit lazy-mount &lt;url&gt; &lt;path&gt; --depth 1\ngit lazy-mount &lt;url&gt; &lt;path&gt; --filter blob:none\ngit lazy-mount &lt;url&gt; &lt;path&gt; --allow-full-object-clone\n</code></pre>\n<hr />\n<h1>6. Subsystems</h1>\n<p>Each subsystem is summarized here at spec altitude; its area document owns the\ndepth.</p>\n<h2>6.1 Worktree model</h2>\n<p><em>Area doc: <a href=\"/git-lazy-mount/worktree-model\"><code>worktree-model.md</code></a>.</em></p>\n<p>The <code>Projection</code> layers the durable overlay over the fixed baseline HEAD tree.\n<code>resolve()</code> follows the order in <a href=\"#52-working-tree-model-baseline--overlay\">§5.2</a>.\n<code>readdir()</code> merges baseline and overlay children at O(direct children) with no\nblob fetch. Overlay entries are <code>File</code> / <code>Symlink</code> / <code>Dir</code> / <code>Tombstone</code> /\n<code>BaseRef{oid,mode}</code>; a clean file or subtree rename is metadata-only (overlay\nre-key plus baseline base-refs at the destination, source tombstoned) and fetches\nno blob contents. <code>RENAME_NOREPLACE</code> is honored; <code>RENAME_EXCHANGE</code> is rejected.\nRepository paths are raw <code>RepoPath</code> byte sequences (never lossily converted to\nUTF-8), so paths with invalid UTF-8, newlines, leading dashes, quotes, and control\ncharacters round-trip correctly.</p>\n<h2>6.2 FUSE semantics</h2>\n<p><em>Area doc: <a href=\"/git-lazy-mount/fuse-semantics\"><code>fuse-semantics.md</code></a>.</em></p>\n<p><code>TransparentFs</code> implements these <code>fuser</code> operations: <code>init</code> (which negotiates\n<code>FUSE_ATOMIC_O_TRUNC</code>), <code>lookup</code>, <code>forget</code>, <code>getattr</code>, <code>setattr</code>, <code>readlink</code>,\n<code>open</code>, <code>create</code>, <code>read</code>, <code>write</code>, <code>flush</code>, <code>fsync</code>, <code>release</code>, <code>mkdir</code>, <code>unlink</code>,\n<code>rmdir</code>, <code>rename</code>, <code>symlink</code>, <code>opendir</code>, <code>readdir</code>, <code>releasedir</code>, <code>access</code>, and\n<code>statfs</code>. Not implemented (these fall through to the <code>fuser</code> default, <code>ENOSYS</code>):\n<code>link</code>, <code>mknod</code>, all xattr ops, <code>fallocate</code>, <code>copy_file_range</code>, <code>lseek</code>, file\nlocking (<code>getlk</code>/<code>setlk</code>/<code>flock</code>), <code>destroy</code>, and <code>batch_forget</code>.</p>\n<p>Handles are real (<code>Handle::Read</code> / <code>Handle::Write</code>, <code>fh</code> from 1, never 0); reads\nand writes are serviced strictly by <code>fh</code> via <code>pread</code>/<code>pwrite</code> into an FD, with no\nwhole-file <code>Vec&lt;u8&gt;</code> buffering. First writable <code>O_TRUNC</code> seeds an empty overlay\nfile with no baseline fetch; a partial overwrite copies up once and then writes in\nplace. Open-unlink and rename-while-open keep working through the FD because\nservice does not depend on a path. Inode identity (<code>InodeTable</code>) is stable across\nrepeated lookups, with a per-inode generation; <code>ROOT_INO = 1</code> is the only\npre-allocated inode. Two fixed bounded pools run callbacks: 16 object-I/O threads\nand 4 metadata threads (so <code>ls</code> stays responsive while reads hydrate). There are\nno separate decompress/filter/network pools and no backpressure/cancellation\nmachinery.</p>\n<h2>6.3 Object fetching</h2>\n<p><em>Area doc: <a href=\"/git-lazy-mount/object-fetching\"><code>object-fetching.md</code></a>.</em></p>\n<p><code>materialize_path</code> streams a baseline blob through <code>cat-file</code> into a\ncontent-addressed cache file and serves range reads from its FD via a\n<code>ContentHandle</code> (<code>pread</code>, bounded RSS). Concurrent faults of the same object are\ncoalesced by a per-<code>ObjectId</code> single-flight map (<code>inflight: Mutex&lt;HashMap&lt;ObjectId, Arc&lt;Mutex&lt;()&gt;&gt;&gt;&gt;</code>), so a hundred concurrent reads of one\nmissing blob cause one retrieval. Smudge/working-tree content is produced by <code>git cat-file --filters --path --attr-source</code>. Fetch eligibility is gated by\n<code>FetchPolicy</code> (<code>CacheOnly</code> / <code>MustNotFetch</code> / <code>AllowNetwork</code> / <code>Prefetch</code>); a\nmissing object under an offline policy maps to a bounded filesystem error\n(<code>OfflineMissingObject → EIO</code>, <code>NotFound → ENOENT</code>).</p>\n<p><code>getattr</code> is the one metadata op that may fault: a Git tree entry carries no exact\nworking-tree size, so <code>ls -l</code> / <code>stat</code> of an unmaterialized file faults its blob\nonce. This is fundamental to lazy-blob fetching and is separate from <code>git status</code>,\nwhich faults zero blobs (next section).</p>\n<h2>6.4 FSMonitor v2 + change journal</h2>\n<p><em>Area doc: <a href=\"/git-lazy-mount/fsmonitor\"><code>fsmonitor.md</code></a>.</em></p>\n<p>Git's FSMonitor v2 hook receives <code>(version, previous_token)</code> and returns a new\ntoken, a NUL, then the relative paths changed since that token. Responses are\n<strong>inclusive</strong>: false positives are acceptable, false negatives are not. The token\nwire form is <code>glm1:workspace:epoch:seq:generation</code>; <code>epoch</code> and <code>generation</code> are\nfixed at 1 and 0.</p>\n<p>The <code>ChangeJournal</code> (<code>&lt;gitdir&gt;/glm-fsmonitor/changes.log</code>) is a durable\nNUL-separated append log replayed into memory on open. <code>record()</code> writes and\n<code>sync_data()</code>s <strong>before</strong> the FUSE reply, so an acknowledged mutation is always\nvisible to the next query. <code>query()</code> returns a full invalidation (<code>/</code>) for any\ntoken it cannot place: an empty token while <code>seq &gt; 0</code>, an unparseable token, a\nworkspace/epoch/generation mismatch, or a <code>seq</code> beyond the current sequence.</p>\n<p><strong>The zero-blob first-status finding (canonical here).</strong> The <em>first</em> clean <code>git status</code> faults zero blobs, the same as every later one. A freshly <code>read-tree</code>'d\nindex carries no FSMonitor extension, so without intervention Git stats (and so\nfaults) every entry on the first status before writing the extension. The fix,\napplied at mount right after <code>read-tree</code>, pre-seeds the FSMonitor index extension\n(<code>seed_fsmonitor_valid</code>): every entry is marked <code>CE_FSMONITOR_VALID</code> carrying the\njournal's seq-0 token, so Git's <code>refresh_cache_ent</code> early-returns before any\n<code>lstat</code> and the hook answers &quot;nothing changed&quot; at the seq-0 token. Two carve-outs\nkeep it correct: (a) checkout conversion attributes\n(<code>filter</code>/<code>ident</code>/<code>working-tree-encoding</code>/CRLF <code>eol</code>) are detected by reading the\ntracked <code>.gitattributes</code> blobs directly; if any path declares such an attribute\nthe entire seed is skipped, so Git's first status checks every path normally and\nnever hides a diff — bounded by a 20-second attribute-read timeout; (b) the seeded token\nmust match the hook's identity, else Git falls back safely to the eager scan.\nVerified zero-fault on an 81k-file real mount.</p>\n<h2>6.5 Git state model</h2>\n<p><em>Area doc: <a href=\"/git-lazy-mount/git-state-model\"><code>git-state-model.md</code></a>.</em></p>\n<p>The transparent design — <code>git clone --separate-git-dir</code> + <code>core.worktree</code> + a\nsynthetic <code>.git</code> gitfile served by the projection — gives stock Git an ordinary\nrepository whose working tree happens to be virtual. Git owns all repository state\n(<a href=\"#51-two-sources-of-truth\">§5.1</a>); the projection owns only working-tree bytes.\nIndex-only updates leave baseline and overlay untouched; working-tree updates\nflow through FUSE into the overlay exactly as ordinary filesystem operations\nwould. We never infer a working-tree update from a changed index.</p>\n<h2>6.6 Index strategy</h2>\n<p><em>Area doc: <a href=\"/git-lazy-mount/index-strategy\"><code>index-strategy.md</code></a>.</em></p>\n<p>The mount uses a <strong>full real index</strong> built by <code>git read-tree HEAD</code> (faulting HEAD\ntrees, fetching zero blobs) — the maximum-compatibility correctness baseline.\n<code>git-store</code>'s <code>interop.rs</code> synthesizes a <em>separate</em> throwaway operational index\n(every entry skip-worktree) only to let stock Git run against the shared store off\nthe mount hot path; it is exercised by the store integration tests, not the FUSE\npath. Overview:\n<a href=\"/git-lazy-mount/architecture\"><code>architecture.md</code></a>. This doc explains the <strong>ownership\nboundary</strong> between stock Git and the mount, and why the transparent\ndesign needs no daemon-side copy of Git state to honor it.</p>\n<hr />\n<h2>1. The one invariant</h2>\n<blockquote>\n<p><strong>INV-OWNERSHIP.</strong> Git owns every piece of repository state — the index,\nHEAD, refs, reflogs, the object database, and in-progress operation state\n(merge/rebase/cherry-pick/bisect). The mount owns only the <em>virtual\nworking-tree bytes</em> (baseline + overlay). Any view the mount holds of\nGit-owned state is a <strong>disposable cache</strong> rebuilt from the real gitdir; the\nmount <strong>never</strong> writes a second authoritative copy and <strong>never</strong> infers Git\nstate into a parallel model.</p>\n</blockquote>\n<p>Three corollaries:</p>\n<ul>\n<li><strong>No second stage.</strong> There is exactly one stage: the real\n<code>$GIT_DIR/index</code>. How the transparent design satisfies the boundary</h2>\n<p>The mount realizes INV-OWNERSHIP not by mirroring Git state into caches, but\nby <em>removing the need to</em>. Stock Git drives the real gitdir directly:</p>\n<ul>\n<li>The clone is <code>git clone --no-checkout --separate-git-dir=&lt;gitdir&gt;</code>\n(<a href=\"https://github.com/linyiru/git-lazy-mount/blob/138cebb4b0555ce1ebec906335fd900a4147c29a/crates/git-repo/src/lib.rs\"><code>AdminRepo::clone</code></a>), so the gitdir is a\nnormal <strong>native</strong> directory outside FUSE.</li>\n<li><code>core.worktree</code> is set to the mountpoint, and the FUSE projection serves a\nsingle synthetic <code>.git</code> <em>gitfile</em> at the mount root pointing back at that\ngitdir.</li>\n</ul>\n<p>The result: when a user runs <code>git add</code>, <code>git commit</code>, <code>git reset</code>, <code>git merge</code>, or <code>git switch</code> inside the mount, <strong>stock Git reads and writes its own\nindex, refs, reflogs, locks, and sequencer/rebase state in the native gitdir\ndirectly.</strong> Git uses its ordinary <code>index.lock</code>, <code>packed-refs</code>, ref locks, and\natomic renames.
